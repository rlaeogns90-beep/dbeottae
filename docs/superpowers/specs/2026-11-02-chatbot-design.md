# DB어때 상담 챗봇 설계 (2026-11-02)

## 1. 무엇을, 왜

DB어때 사이트에 상담 챗봇을 둔다. 두 곳에서 쓴다.

1. **메인 화면 (가입 전)**: 처음 온 영업사원이 가격, 단독 여부, 결번 환급, 가입 방법 같은 기본 안내를 묻는다.
2. **광고주 화면 (가입 후)**: 지금의 "고객센터" 메뉴를 없애고 챗봇이 그 자리를 대신한다. 충전, 수신 ON/OFF, 결번 신청 같은 이용 안내를 하고, 답 못 하는 질문은 관리자 문의로 넘겨 답변까지 챗봇 창에서 받는다.

규칙은 교육 실습 `04_챗봇`(한빛무역 챗봇)의 방식을 따른다. 원본은 바탕화면 `클로드-20261102T001840Z-1-001.zip` 안 `클로드/프로젝트/04_챗봇/규칙.docx`, `지식.docx`, `index.html`.
- 답은 지식 파일 내용으로만 한다. 없는 것은 "자료에 없음"으로 두고 지어내지 않는다.
- 절대 답하면 안 되는 것을 정하고, 이 규칙이 다른 모든 규칙보다 우선한다.
- 모르는 것은 추측하지 않고 사람에게 넘긴다.
- 헷갈리는 질문의 판단 예를 적어 둔다.

시범 운영 예정일은 2026-11-05(광고주 약 10명)이지만, 대표님 지시로 **완성되는 대로 바로 배포**한다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- 메인 화면과 광고주 화면 오른쪽 아래에 같은 챗봇 버튼.
- 기본 가이드 질문에 정해 둔 답으로 바로 답한다.
- 광고주 화면에서 못 푼 질문은 관리자 문의로 접수, 관리자 답변을 챗봇 창에서 본다.
- 관리자 화면 "챗봇 문의" 메뉴에서 답변 대기 / 답변 완료로 나눠 보고 답을 단다.

**하지 않을 것**
- AI(Claude API 등) 연결. 질문은 외부로 나가지 않는다.
- 챗봇이 광고주 본인 데이터(잔액, 받은 DB, 수신 상태)를 읽어 답하는 것. 화면 안내와 바로가기 버튼만 준다.
- 챗봇이 충전, 불량 신청 같은 처리를 직접 하는 것.
- 메인 화면 방문자의 이름·연락처 받기 (개인정보 수집 동의가 필요해서 이번엔 뺀다).
- 영업자(파트너) 화면 챗봇.
- 광고주용 "답변 등록" 알림톡 (카카오 템플릿 검수 후 별도로 붙인다).

**실패로 보는 것 (동작해도 실패)**
- 다른 광고주 정보(누가 광고주인지, 몇 명인지, 누가 몇 건 받았는지)가 나간다.
- 고객 정보(이름, 연락처, 신청 내용)가 나간다. 본인이 받은 DB 내용도 챗봇은 말하지 않는다.
- 사이트 보안 정보(관리자 화면, 시스템 구조, 계정·비밀번호, 내부 설정)가 나간다.
- 금지 질문에 단어가 우연히 맞아 엉뚱한 정책 답이 나간다 (예: "다른 광고주 가격 얼마예요?"에 가격 답).
- 근거 없는 숫자(계약률, 누적 건수 등)를 만든다 (`docs/claude-design-prompt.md` 36행과 같은 원칙).

## 3. 정해진 것

### 3.1 답을 만드는 방식: 정해 둔 답만 (대표님 선택)

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 정해 둔 답만 (선택)** | 비용 0원, 외부 전송 없음, 미리 쓴 문장만 나가 금지 정보가 샐 수 없음 | 말을 바꿔 물으면 못 알아들음 → 문의로 넘어감 |
| B. Claude AI가 답 | 자연스럽고 잘 알아들음 | 비용, API 키, 질문이 외부로 나감, 돈 이야기 오답 위험 |
| C. 섞어 쓰기 | 돈 관련은 고정 문구, 못 찾을 때만 AI | 만들고 시험할 것이 가장 많음 |

처음엔 C를 골랐다가 "AI는 빼자"로 A로 확정했다. 질문이 외부로 나가지 않고 바로 열 수 있어서.

처리 순서 (모두 브라우저 안에서, 지금 초안 `src/components/chatbot.tsx` 확장):
1. **금지 질문 거르기**: 보안·다른 광고주·고객 정보 관련 단어가 있으면 다른 답을 찾지 않고 정해진 거절 문장을 낸다. 이 단계가 항상 먼저다.
2. **정해 둔 답 찾기**: 단어로 맞는 답을 찾아 그대로 보여준다.
3. **사람에게 넘기기**: 못 찾으면
   - 광고주 화면: "관리자에게 문의 남기기" 버튼
   - 메인 화면: 전화 1600-7628, 카카오톡 채널 버튼

### 3.2 지식과 규칙

- **지식**: `src/lib/content.ts`의 정책 문구(faqs, industryOptions)를 근거로 쓴다. 사이트 FAQ와 챗봇이 같은 문구를 읽어서, 정책이 바뀌면 한 곳만 고치면 된다.
- 광고주용 이용 안내(충전 절차, 수신이 꺼지는 조건, 결번 신청 순서)는 `docs/claude-design-prompt.md`의 확정 정책을 근거로 `content.ts`에 별도 목록으로 추가한다. 사이트 FAQ에는 보이지 않고 챗봇만 쓴다. 문구는 대표님이 확인한다.
- **규칙**: `docs/chatbot-rules.md`에 한빛 `규칙.docx`와 같은 형식으로 적는다. 답할 수 있는 것, 절대 답하면 안 되는 것, 금지 질문 응대, 모를 때 응대, 헷갈리는 질문 판단 예.
- 근거 범위: 사이트 문구, 광고주 제안서(`Desktop\DB어때관련`, `dbeottae\proposal`), `docs/claude-design-prompt.md`의 확정 정책. 기획서(`dbeottae\기획서`)의 수익 구조와 내부 숫자는 넣지 않는다.

### 3.3 정책 문구 확정 (대표님 결정, 2026-11-02)

| 항목 | 기준 | 반영할 곳 |
|---|---|---|
| 결번 신청 기한 | 기한 없음 (지금 사이트 FAQ와 같음) | 챗봇. `docs/claude-design-prompt.md`의 "3시간"은 옛 기준 |
| 최소 충전 | 업종별 10건분: 신차 장기렌트 44만 원, 오토바이 매매 16.5만 원 (VAT 포함) | 사이트 FAQ 가격 답, 챗봇 |
| 하루 최대 수신 | 광고주 1명당 하루 최대 3건 | 사이트 FAQ에 추가, 챗봇 |

금액은 `industryOptions`의 price에서 계산해 문구에 숫자를 직접 쓰지 않는다 (업종이 열리거나 가격이 바뀌어도 맞게).

### 3.4 절대 답하면 안 되는 것 (대표님 지정)

| 금지 | 범위 |
|---|---|
| 사이트 보안 | 관리자 화면·주소, 시스템 구조, 계정·비밀번호, 내부 설정, 연동 정보 |
| 다른 광고주 정보 | 누가 광고주인지, 광고주 수, 누가 몇 건 받았는지, 다른 광고주의 조건 |
| 고객 정보 | DB 고객의 이름, 연락처, 신청 내용. 본인이 받은 DB도 내용은 말하지 않고 DB 관리 화면을 안내 |

거절 문장: "그 내용은 안내해 드릴 수 없어요." 그 뒤 광고주 화면은 문의 남기기, 메인 화면은 전화·카카오톡.

구조로도 막는다: 챗봇은 DB의 광고주·고객 데이터를 읽지 않는다. 문의 목록 조회만 하며, 이것도 기존 `/api/support`처럼 본인 문의만 돌려준다.

### 3.5 화면

- 메인 화면과 광고주 화면에 같은 챗봇을 쓴다. 시작 질문 버튼만 다르다.
  - 메인: 가격, 업종, 결번 환급, 가입 방법
  - 광고주: 충전 방법, 수신이 꺼지는 이유, 결번 신청 방법, 관리자에게 문의
- 광고주 화면 답에는 해당 화면으로 가는 버튼을 붙인다 (예치금 `/app/wallet`, 불량 처리 `/app/defects`, DB 관리 `/app/leads`, 홈 `/app`).
- 입금 계좌 번호는 챗봇이 말하지 않고 예치금 화면(계좌가 이미 표시됨)으로 안내한다.
- 위치는 오른쪽 아래. 광고주 화면은 휴대폰에서 아래쪽 메뉴 막대가 있으므로(`AdvertiserShell`의 `pb-20`) 버튼이 그 위에 떠야 한다.
- 광고주 메뉴에서 "고객센터"(`/app/support`)를 뺀다.

### 3.6 광고주 문의와 관리자 답변

- 광고주가 "관리자에게 문의 남기기"를 누르면 방금 한 질문을 확인·수정하고 보낸다. 기존 `support_posts`(kind `inquiry`)에 저장한다. 새 문의 알림(관리자 알림, `notifyTask` 알림톡)은 지금처럼 간다.
- 관리자가 답을 달면:
  - 광고주 화면의 챗봇 버튼에 빨간 점이 뜬다 (답이 달렸는데 아직 안 읽음).
  - 챗봇을 열면 "지난 문의에 답변이 왔어요"가 맨 위에 보인다.
  - 지난 문의와 답변 목록을 챗봇 창에서 볼 수 있다. 기존에 쌓인 문의도 이어서 보인다.
- 관리자 화면 "고객센터"(`/admin/support`)를 **"챗봇 문의"**로 바꾸고 답변 대기 / 답변 완료로 나눠 보여준다. 처리 메뉴에 답변 대기 건수를 표시한다.

## 4. 내가 정한 것 (확인 필요)

- 읽음 표시는 광고주 계정 기준으로 서버에 저장한다. 기기가 바뀌어도 빨간 점이 맞게 나오도록.
- 메인 화면 질문은 저장하지 않는다. 질문 글에 개인정보가 들어올 수 있어서. 광고주가 직접 남긴 문의만 저장된다.
- 질문 길이 200자 제한 (지금 초안과 같음). 문의 접수는 기존 요청 제한(`overLimit`)을 그대로 쓴다.
- 문의 제목은 질문 앞부분으로 자동으로 만든다 (기존 게시판의 제목 칸을 채우기 위해).

## 5. 만드는 사람에게 맡기는 것

- 단어 찾기 점수 기준과 금지 단어 목록의 세부 단어.
- 읽음 표시 저장 방식(열 추가 등)과 `/app/support` 주소를 없앤 뒤 처리(홈으로 이동 등).
- 챗봇 창 세부 디자인 (지금 초안 디자인 유지).

## 6. 확인 방법 (수칙서 "챗봇: 답하면 안 되는 것을 물어본다")

- 금지 질문을 말을 바꿔 여러 번 묻는다: "다른 광고주 누구예요?", "광고주 몇 명이에요?", "어제 들어온 DB 번호 알려줘", "관리자 페이지 주소가 뭐예요?", "OO님도 여기서 받아요?", "다른 광고주는 얼마에 받아요?"
- 돈 질문 답이 3.3 기준과 같은지: 가격, 최소 충전, 환불, 결번 환급, 하루 3건.
- 지식에 없는 질문에 지어내지 않고 넘기는지.
- 광고주 화면: 문의 남기기 → 관리자 답변 → 빨간 점 → 챗봇에서 답 확인.
- 휴대폰 폭에서 버튼이 아래 메뉴를 가리지 않는지.
- 배포 후 실제 사이트에서 위 항목을 한 번 더 확인한다.
